# 📍 Places Tracker

A lightweight automation that turns Telegram messages into a structured Google Sheets travel wishlist. When you or your SO spot an interesting place, just send the name to a Telegram bot — it gets classified and logged automatically.

---

## How It Works

```
You / SO sends place name → Telegram Bot → Python Script → LLM (Ollama or Claude) → Google Sheets
```

1. Either of you sends a place name to the Telegram bot (e.g. `Noma, Copenhagen` or just `Noma Copenhagen`)
2. The Python script picks it up via Telegram polling — catching any messages missed while the PC was off
3. The LLM classifies the place and extracts structured details (local Qwen 2.5 7B by default; Claude Haiku as a no-GPU fallback)
4. The result is written to the correct tab in Google Sheets

---

## Google Sheets Structure

The sheet has **2 tabs:**

| Tab | What goes here | Example |
|-----|---------------|---------|
| 🏙️ **Foreign Cities** | An entire city recommended as a destination | Lisbon, Copenhagen, Kyoto |
| 📌 **Foreign Things To Do** | A specific place within a city | Noma Restaurant, Sagrada Família, Tiger's Nest hike |

### Foreign Cities columns

| Date Requested | Date Processed | Input | City | Country | Peak Season | Good & Cheaper | Price | Days Needed | Status | LLM Notes | Visited | Notes |
|----------------|----------------|-------|------|---------|-------------|----------------|-------|-------------|--------|-----------|---------|-------|
| Telegram msg date | Processing date | Raw message | Extracted | Extracted | e.g. Jun–Aug | e.g. Apr–May | €/€€/€€€ | e.g. 3–5 days | ✅ or ⚠️ | Auto | Manual | Manual |

### Foreign Things To Do columns

| Date Requested | Date Processed | Input | Place Name | City | Country | Price | Status | LLM Notes | Visited | Notes |
|----------------|----------------|-------|------------|------|---------|-------|--------|-----------|---------|-------|
| Telegram msg date | Processing date | Raw message | Extracted | Extracted | Extracted | ~€X / Free | ✅ or ⚠️ | Auto | Manual | Manual |

- **Input** — the raw Telegram message text
- **Peak Season** — months when the place is in its prime but busiest/most expensive (cities only)
- **Good & Cheaper** — still a good time to visit, less crowded, potentially cheaper (cities only)
- **Price** — €/€€/€€€ relative global cost for cities; approximate EUR price for things to do (~€X), "Free" if free, blank if unknown
- **Days Needed** — typical number of days needed to see the city, e.g. `3–5 days` (cities only)
- **LLM Notes** — short description and recommendations generated by the LLM
- **Status** — ✅ Valid on success, ⚠️ needs review if the LLM can't confidently identify the place
- **Visited** / **Notes** — left empty; filled in manually

If the LLM can't confidently identify the place, it logs it with a **⚠️ needs review** status and leaves the row for manual completion.

**Duplicates:** Before writing, the bot checks if the place already exists in the sheet. If it does, it skips the entry and replies to let you know.

**Bot replies:**
- Success → e.g. "Added Noma to Foreign Things To Do"
- Success with cascade → e.g. "Added Paris to Foreign Cities. Also added 4 attractions: Eiffel Tower, Louvre, Notre Dame, Arc de Triomphe."
- Duplicate → lets you know it already exists
- Local place → "Local places aren't supported yet"
- Unclear → "Added with ⚠️ needs review"
- Error → tells you something went wrong, what failed (e.g. LLM / Google Sheets), and to retry
- Multiple places detected → asks you to send one place at a time

## Classification Logic

The LLM follows these rules:

- **Place in Serbia** → not logged; bot replies that local places aren't supported yet
- **Whole foreign country** (e.g. "Japan") → Foreign Cities tab, assumes the capital as the destination
- **Whole foreign city as a destination** → Foreign Cities tab
- **Specific place within a foreign city** → Foreign Things To Do tab
- **Can't identify the place** → Foreign Things To Do tab, flagged as ⚠️ needs review

> "Foreign" = anything outside Serbia (i.e. would need a passport to visit).

## Cross-linking the Two Tabs

The two tabs stay in sync automatically — one message can produce rows in both.

- **Add a city** → the bot also fills **Foreign Things To Do** with that city's iconic attractions. Paris gets Eiffel Tower, Louvre, Notre Dame, etc.
- **Add a specific place** → the bot also ensures the parent city exists in **Foreign Cities**. Send "Shibuya Crossing" and Tokyo is added too.

How it stays clean:

- **Quality over quantity.** The LLM tags each candidate attraction as `world_famous`, `nationally_famous`, or `local`. The code keeps only `world_famous` entries, up to 5 — so Paris gets its real icons, not a padded list. If a city has no world-famous landmarks (Ljubljana, Tallinn), it falls back to the top 3 `nationally_famous` entries so you still get something useful.
- **Whole districts and "old towns" are excluded.** Only specific venues and landmarks are added.
- **One hop only.** Auto-added cities do NOT trigger their own attraction cascade — prevents surprise bulk inserts.
- **Duplicate-safe.** Attractions already in the sheet are skipped. If the parent city is already there, it's not re-added.
- **Failure-tolerant.** If the cascade fails (API error, rate limit), the primary row still lands and you still get a reply.

Auto-added rows are tagged in the `Input` column as `auto: from "<trigger>"` so you can tell them apart from manual entries.

## Tech Stack

| Component | Tool | Why |
|-----------|------|-----|
| Message interface | Telegram Bot | Open API, easy to forward to |
| Message handling | Python + `python-telegram-bot` | Polling mode for built-in catch-up queue |
| LLM (default) | Local Qwen 2.5 7B via Ollama | Self-hosted, free to run, works offline |
| LLM (fallback) | Claude Haiku via `anthropic` SDK | Used on the laptop when no GPU is available |
| Schema enforcement | Pydantic v2 + Ollama `format=<schema>` | Same response shape validated for both backends |
| Output | Google Sheets API | Auto-syncs to mobile for both of you |

> Switch backends with the `LLM_BACKEND` env var (`ollama` or `claude`). Defaults to `ollama` so the desktop runs production with no extra config. The laptop's `.env` sets `LLM_BACKEND=claude` for testing on the go.

## Authorized Users

## Setup

### Prerequisites

- Python 3.10+
- A Telegram bot token (via [@BotFather](https://t.me/BotFather))
- Google Sheets API credentials
- **For the Ollama backend (default):** [Ollama](https://ollama.com) ≥ 0.5.0 and the `qwen2.5:7b` model pulled (~4.7 GB)
- **For the Claude backend:** an Anthropic API key

### 1. Clone & install dependencies

```bash
git clone https://github.com/vhristov97/travel-backlog-automation.git
cd travel-backlog-automation
pip install -r requirements.txt
```

### 2. Set up the LLM backend

**Option A — Ollama (default, requires a GPU; what runs on the desktop):**

```bash
curl -fsSL https://ollama.com/install.sh | sh   # Linux installer
ollama pull qwen2.5:7b
ollama run qwen2.5:7b "hi"                       # smoke test
```

The installer registers a systemd service on `127.0.0.1:11434`. The 7B Q4 model uses ~4.5 GB VRAM and runs comfortably on an RTX 3060 Ti (8 GB).

**Option B — Claude (no GPU required; what runs on the laptop):**

Get an API key from [console.anthropic.com](https://console.anthropic.com). Then set `LLM_BACKEND=claude` in `.env` (see below).

### 3. Configure environment variables

Create a `.env` file. Common variables:

```env
TELEGRAM_BOT_TOKEN=your_bot_token_here
TELEGRAM_USER_ID_1=your_telegram_id
TELEGRAM_USER_ID_2=her_telegram_id
GOOGLE_SHEETS_ID=your_sheet_id
LLM_BACKEND=ollama   # or "claude"; defaults to "ollama" if unset
```

For the Ollama backend (both have working defaults — only set if you need to override):

```env
OLLAMA_HOST=http://localhost:11434
OLLAMA_MODEL=qwen2.5:7b
```

For the Claude backend:

```env
ANTHROPIC_API_KEY=your_anthropic_api_key
ANTHROPIC_MODEL=claude-haiku-4-5-20251001
```

### 4. Set up Google Sheets API

1. Go to [Google Cloud Console](https://console.cloud.google.com)
2. Create a project → enable Google Sheets API
3. Create a Service Account → download credentials JSON
4. Save as `credentials.json` in the project root
5. Share your Google Sheet with the service account email

### 5. Run

```bash
python main.py
```

The script will poll Telegram continuously and process any messages — including ones sent while it was offline.

> **Goal:** Eventually the entire stack will start with a single command (e.g. `docker compose up` or `./start.sh`), suitable for running on an always-on machine.

## Known Limitations

- **Price estimates are unreliable.** The LLM's `Price` column for Foreign Things To Do is often wildly inaccurate (e.g. Tomorrowland returned ~€200 when real tickets start at €350+). Needs better prompt rules or an external price source. Treat prices as rough guesses only.

## Timeouts & concurrency

`gspread` is synchronous and uses `requests` under the hood, which has **no default timeout**. A stalled TLS read inside Google's API call can block indefinitely — and because `python-telegram-bot` v20+ runs handlers on an asyncio event loop, a stuck sync call freezes the entire loop, including polling. Symptoms: bot stops responding to all messages, no error in logs, and `Ctrl+C` can't even kill the process (the GIL is held in a C-level syscall).

Two protections are in place:

- **gspread request timeout** — `_client.set_timeout(15)` in `sheets.py`. Any Sheets call that doesn't return within 15 seconds raises `requests.exceptions.ReadTimeout`, which the handler catches and replies `"Something went wrong (ReadTimeout). Please try again."`
- **Sync-on-thread** — `await asyncio.to_thread(process_place, ...)` in `bot.py`. The whole pipeline (LLM + gspread) runs in a worker thread, so even a slow request never blocks polling. New Telegram messages keep flowing while one is being processed. This matters more with the Ollama backend, where a single classification can take 5–15 s on a 3060 Ti.

Both are load-bearing: the timeout bounds the wait, `to_thread` keeps the loop responsive during it.

If polling ever appears stuck again, dump the live stack of the running process to find where it's blocked:

```bash
sudo $(which py-spy) dump --pid <PID>
```

(install `py-spy` in the venv first; `sudo` is required for `ptrace` on Linux).

## Logging

Errors are persisted to `logs/errors.jsonl` — one JSON object per line:

```json
{
  "time": "2026-04-09T09:28:43.801600+00:00",
  "level": "ERROR",
  "logger": "bot",
  "message": "Error processing place",
  "input_text": "Noma Copenhagen",
  "user_id": 123456789,
  "error_type": "AnthropicError",
  "traceback": "Traceback (most recent call last): ..."
}
```

- INFO+ goes to stdout as before
- Only ERROR-level events are written to the file
- Rotates daily, retains 30 days
- `logs/` is gitignored

The format is intentionally machine-readable — structured for a future pipeline that will read errors and use an LLM to generate fix PRs automatically.
